# 3.0.0-rc1

这是 3.0 的首个发布候选，汇集自 2.2.0 以来的订阅、下载、媒体整理、播放、家庭档案与运维改进，供正式版前试用和反馈。候选版不代表 3.0 稳定版验收完成；新装、从 `v2.2.0` / `pre-2.2.0.130` 升级及灾难恢复演练仍需单独记录，构建与自动化验证不能代替这些结果。

## 主要变化

- **新的追番工作台**：整合继续观看、按番剧分组的媒体库、下载与订阅概览，更新导航、移动端布局、可访问性与 SVG 标识；大媒体库和虚拟文件目录采用分页与按需加载。
- **订阅与缺集补全**：按播出日期区分未播、缺集和资源状态，支持逐集选择候选、批量提交与失败重试；番剧级多来源订阅支持主字幕组、等待期限和备选来源，结合质量规则与版本升级流程。
- **元数据与媒体整理**：支持现有媒体目录导入、人工审核、纠错预览与撤销，以及限定订阅源、标题或字幕组的长期识别规则。导入通过虚拟映射整理媒体，保留原文件路径。
- **观看与文件访问**：支持播放进度、自动下一集、服务端 HLS、外部播放器入口、媒体版本绑定的 OP/ED 区间与章节；大文件交给浏览器原生下载管理器，符合条件的存储支持 Range 续传。提供只读 WebDAV、VFS、Linux FUSE 与 NFS 入口。
- **家庭账户与个人追番**：增加 Admin / Member / Viewer 角色、独立档案、会话撤销及受限设备凭据；播放与聊天状态、追番清单按档案保存，媒体库共享。清单支持想看、追更、搁置、弃番、看完及本周更新视图。
- **AI 配置与操作确认**：支持多个独立命名的 Provider，并在聊天和 AI 任务中选择模型与推理强度；支持 OpenAI Responses、兼容 Chat Completions、Anthropic 与 Codex app-server。自动推理可单独设置默认选择，AI 写操作经过服务端确认与审计。
- **持续运行与恢复**：增加持久任务、租约、通知 Outbox、统一待办与异常入口、备份恢复工具和受控插件平台；下载使用持久容量队列、自适应轮询与有界完成处理，迁移支持串行执行与 checkpoint 恢复。

操作入口和详细边界见 [订阅、下载与观看](https://github.com/HCGStudio/SecondDimensionWatcherReDive/blob/v3.0.0-rc1/docs/library-workflows.md)、[AI Provider 配置](https://github.com/HCGStudio/SecondDimensionWatcherReDive/blob/v3.0.0-rc1/docs/ai-providers.md) 与 [安全边界](https://github.com/HCGStudio/SecondDimensionWatcherReDive/blob/v3.0.0-rc1/docs/security-boundaries.md)。

## 新安装

从本次 Release 选择对应平台的附件，并用 `SHA256SUMS` 校验；容器固定使用 `ghcr.io/hcgstudio/sdw-redive:3.0.0-rc1` 或本次 Release 记录的 digest。候选版不会推广到稳定版 `latest`，部署模板中的镜像标签须显式改为该候选版本。

系统包需要 ASP.NET Core 10 Runtime、PostgreSQL、qBittorrent Web API 和 FFmpeg；容器已包含应用运行时与 FFmpeg。配置数据库、JWT 和下载目录，持久化数据库及 `StateDirectory`，保证应用能访问 qBittorrent 实际写入的下载卷。首次打开网页注册管理员，再在「设置」配置下载器、TMDB、AI 等功能。部署步骤见 [服务器部署](https://github.com/HCGStudio/SecondDimensionWatcherReDive/blob/v3.0.0-rc1/docs/server-deployment.md) 和 [容器部署](https://github.com/HCGStudio/SecondDimensionWatcherReDive/blob/v3.0.0-rc1/docs/container-deployment.md)。

## 从 2.2.0 升级与配置迁移

1. 停止旧应用及所有副本，保留 PostgreSQL 一致性备份、实际使用的部署配置、旧密码文件和 Data Protection 密钥环。`v2.2.0` 尚未附带 `sdw-backup`，可使用 `pg_dump --format=custom` 并独立备份配置与状态文件；已有备份工具的预发布版本按其文档创建并验证归档。媒体、qBittorrent 状态与完整插件运行数据另外备份。
2. 安装候选版并保留原数据库、挂载与状态目录。应用发布版本为 `3.0.0-rc1`，**配置结构版本为 `3.0.0`**；旧配置沿 `2.2.0 → 2.2.1 → 2.3.0 → 3.0.0` 迁移，最后一步仅推进配置版本，不修改其他字段，不能手改 `Version` 跳过迁移。
3. 启动只接受能够完整静默执行的配置迁移；需要选择新旧冲突值、只读配置无法写入或迁移失败时会停止启动。使用 `sdw-migrate`，按实际优先级通过 `--inherit-config` 提供完整底层配置，完整独立文件才使用 `--standalone`；`--working-directory` / `--content-root` 填原服务实际目录。迁移会保留原配置备份，详细命令见 [配置迁移指南](https://github.com/HCGStudio/SecondDimensionWatcherReDive/blob/v3.0.0-rc1/docs/configuration-migrations.md)。
4. 配置迁移保留旧 AI 模型、预算和协议语义，迁移旧密码文件引用及状态路径；升级后账户和凭据由数据库管理。新版 `AI:Providers` 支持命名实例，旧单 Provider 配置仍可读取，首次保存新版 Provider 列表时转换凭据。环境覆盖使用 `SDW_CONFIG_VERSION=3.0.0`，不能用通用 `VERSION` 代替；当前 `Inference:Model` 是推理任务覆盖，未声明版本的旧同名字段会按旧结构迁移。
5. 启动后依次执行数据库 schema 与数据迁移；阻断失败时服务不会开放 HTTP。排除挂载、权限、空间等故障后重启，版本化数据迁移从已保存的 checkpoint 恢复。确认 readiness、登录、加密设置、订阅、文件访问和播放，再为升级后的 3.0 实例重新创建备份。详见 [数据库迁移运维](https://github.com/HCGStudio/SecondDimensionWatcherReDive/blob/v3.0.0-rc1/docs/migrations.md)。

`v2.2.0` 和 `pre-2.2.0.130` 是发布计划的基准升级来源，不据此承诺所有历史预发布均可直接升级。

## 已知限制与恢复

- 下载容量管理默认开启并保留 5 GiB 安全余量；须关闭 qBittorrent 独立未完成目录。无法确认实际下载卷、资源大小未知或空间不足时，任务保持等待。`DownloadCapacity:LocalVolumePath` 只能指定实际下载卷在应用中的共享挂载。关闭容量管理后，新下载绕过准入，已有未暂停队列继续排空；HLS 仍保留独立容量预留。
- 缺集候选仅来自已收录资源；播出资料未知时会明确标注，合辑及季集信息不可靠的条目需要人工处理。自动选用备选字幕组后，晚到的其他来源需要人工选择。OP/ED 和章节由用户维护，季模板须针对具体媒体版本确认后复用。
- Viewer 可浏览与播放，不能保存进度、清单或偏好。WebDAV / VFS 设备凭据可限制虚拟根目录；NFS 依赖受信网络，不使用家庭账户认证。下载票据过期、会话撤销或文件版本改变后，后续续传需要重新生成入口。
- 插件 API 1.0 当前接入通知和存储 Provider；WebDAV 写入、内置种子引擎、外部种子搜索、任意远程脚本加载及插件下载/元数据 Provider 不在本版范围。
- `sdw-backup restore` 默认要求相同应用 major 并核对精确 schema；逻辑 JSON 导入也拒绝跨 major。2.x 归档应先在匹配版本与 schema 的实例恢复，再升级到 3.0；2.x 逻辑导出先导入兼容 2.x 实例，再升级。逻辑导出不能替代完整备份，追番、媒体时间段、多来源决策和容量队列等状态仅随完整数据库恢复。
- 回退应用包或镜像不会回退数据库。需要返回 2.x 时，停止所有副本，恢复升级前数据库、密钥和配置，再运行对应旧版本；不要强制删除新结构或移动已发布标签。数据库归档不包含下载媒体、导入原文件、qBittorrent 数据或完整插件运行数据，须从独立备份恢复并重新对账。步骤见 [备份与恢复](https://github.com/HCGStudio/SecondDimensionWatcherReDive/blob/v3.0.0-rc1/docs/backup-restore.md)。
